# folio-2025: content, interface, onboarding, audio, achievements, server

Source studied: `brunosimon/folio-2025`, sparse checkout at HEAD `70764a9` (2026-11-04). The checkout holds `sources/`, `scripts/` and the root files only. The `static/` folder (models, textures, sounds, UI images) was deliberately not downloaded, and the server code is not public.

Conventions used in these notes:

- Paths are relative to the repo root, cited as `path:line`.
- A statement with a citation was read in the code (VERIFIED). A statement tagged **INFERRED** is a conclusion I drew from the code without running it, or one that depends on assets or server code that are not in the checkout. Nothing was executed.
- "Transfer" always means: transfer to a small, statically hosted, 16-bit-style React portfolio whose content must stay readable as plain semantic HTML, with synthesised audio and no backend. Only techniques and structure are considered; none of Bruno's models, textures, sounds, text or level layout.

Terms used (the first three are Bruno's own names, the rest are mine):

- **Interactive point**: a floating diamond marker in the world, with a text label, that the visitor can activate (class `InteractivePoints`).
- **Area**: one named zone of the world with its own class (Landing, Projects, Lab, ...), built from one child of a single `areas` GLB file.
- **Reference**: an object inside a GLB whose name starts with `ref` or `reference`. Code looks references up by name and uses them as anchors (a position, a radius, a mesh to re-material).
- **Input filter**: a named input context (`intro`, `wandering`, `racing`, `cinematic`, `menu`, `modal`). An input action fires only when one of its categories is in the set of active filters.
- **Cinematic view**: a content mode in which the camera leaves the player and glides to a fixed framing in front of a content board. Projects and Lab use it.
- **DOM panel**: HTML laid over the canvas (the menu or a modal), as opposed to content drawn inside the canvas.
- **Shade mix**: a shader uniform that blends a lit material toward its flat, unlit colour so that content stays legible whatever the time-of-day lighting is.
- **One-ahead prefetch**: loading the next image in the current browsing direction as soon as the current image has finished loading.

## 1. Summary (max 10 bullets)

- **The portfolio content is not in the HTML.** Projects, Lab and Social links live only in JavaScript data modules and are drawn into the canvas; Career is baked into six textures plus GLB metadata. `index.html` contains one short About block, the controls tables, credits, and UI chrome: 19 anchors (17 in the credits, 2 for Discord), none of them to a project and none to the other seven social destinations, no `<h1>`, no `<noscript>`, no ARIA, no landmark elements (`sources/index.html:225-233`, `:682-731`, `:838`, `:851`).
- **Two delivery modes coexist.** (a) In-canvas cinematic views for Projects and Lab, with text rendered canvas-to-texture; (b) DOM panels over the canvas for About, Options, Controls, Achievements, Whispers and credits, opened either from a menu button or from an interactive point in the world. Mode (b) is the one that keeps content readable and is the one worth borrowing.
- **Interactive points are one small factory**: `create(position, label, align, state, onInteract, onReveal, onConceal, onHide)`, three states (hidden, concealed, open), a proximity radius of 2.5 world units, and four activation routes: keyboard Enter/E/F, gamepad cross/A, mouse hover-and-click from any distance, and a DOM "Interact" button on touch. They are not reachable by Tab or by a screen reader.
- **Game input is suspended by swapping input filters**, not by pausing. Opening the menu sets the filter set to `{menu}`, so driving actions stop matching. The filter set, the input device, the gamepad brand, mute and server status are all mirrored as classes on `<html>`, so CSS reacts without JavaScript.
- **One class owns Escape/back.** `ClosingManager` walks an ordered chain (flag picker, modal, menu, race, Projects, Lab) and opens the menu if nothing was open. Menu and modals are mutually exclusive.
- **Onboarding has no DOM loader.** A ring on the ground fills as 40 files load; then a "start" gesture (click the ring, Enter, some movement keys, gamepad cross) both unlocks audio and switches the filter from `intro` to `wandering`. Control hints are device-specific images. The visitor always spawns at the Landing area; position is never saved.
- **Audio is Howler over 81 referenced mp3 files**, organised as a registry of items with groups, an anti-spam interval, an `onPlay` hook (randomise per play) and an `onPlaying` hook (bind volume and rate to game state every frame). Positional audio is manual: camera-relative `pos()` plus a linear distance fade. Mute persists in `localStorage`; window blur mutes and pauses the music. The registry and hooks map well onto synthesised voices; the files and Howler do not.
- **Achievements are fully client-side**: 38 entries in 33 groups defined as tuples, four "unique" groups backed by a `Set` (visit all 13 areas, view every project, ...), one JSON blob in `localStorage`, a toast plus confetti plus sound on unlock, six cosmetic rewards at evenly spaced thresholds, and a triple-confirm reset. Nothing here needs a backend.
- **Server features are optional extras over WebSocket + msgpack**: visitor messages ("whispers"), a daily race leaderboard, two global counters, a server-triggered world event and promo "eggs". The client degrades through an `is-server-offline` class. None of this is possible on a static host without a backend.
- **Accessibility and fallback are minimal**: no reduced-motion handling, no focus styles, no focus trap or restore, no error path if the renderer or a resource fails, and a blank page with JavaScript off.

## 2. Aspects

### 2.1 Content model (the data files)

- **What the visitor experiences:** Nothing directly. These files decide what the Projects board, the Lab board, the Social ring, the achievements list and the flag pickers show.
- **How it works:**
  - `data/projects.js` exports an array of 8 active entries (a ninth is commented out). Each entry has `title` (string), `titleSmall` (an array of lines, or in one case a plain string, used on the "previous/next project" signs), `url`, `attributes` (an object with optional `role`, `at`, `with`, each a string or an array of strings), `distinctions` (array drawn from `'awwwards' | 'fwa' | 'cssda'`, may be empty) and `images` (array of 3 to 5 file names ending in `.ktx`; 27 file names in total). The image path is built as `projects/images/<name>`.
  - `data/lab.js` exports 13 entries: `title`, `url`, `image`, `imageMini`. Paths are `lab/images/<name>`.
  - `data/social.js` exports 8 entries: `name`, either `url` or `modal`, and `align` (`'left' | 'right'`, the side on which the label unfolds). One entry is a `mailto:` URL; one (`Discord`) names a modal instead of a URL.
  - `data/achievements.js` exports 38 tuples `[groupName, title, descriptionHtml, total, unique?]`. It imports the projects and lab arrays so that two totals follow the data length automatically.
  - `data/countries.js` exports 259 tuples `[englishName, localName, code]`, used only by the flag picker (`InputFlag`); the flag image is `ui/flags/<code>.webp`. The last nine entries are joke entries.
  - `data/consoleLog.js` holds a hand-written ASCII banner that repeats the social links and credits as console text.
  - **Career has no data file.** Each career entry is a group in the areas GLB carrying `userData.size`, `userData.hasEnd`, `userData.color` and `userData.texture`; the text is one pre-rendered texture per entry (six of them), loaded with the main resource batch.
  - There is no single source of truth: the social links are maintained by hand in `data/social.js`, in `data/consoleLog.js`, and (for Discord) in `index.html`.
- **Evidence:** `sources/data/projects.js:1-162` (commented entry at `:21-38`, string `titleSmall` at `:129`, empty `distinctions` at `:102`); `sources/data/lab.js:1-80`; `sources/data/social.js:1-10`; `sources/data/achievements.js:1-238` (imports at `:1-2`, derived totals at `:23` and `:30`); `sources/data/countries.js:1-262` (joke entries `:253-261`); `sources/Game/InputFlag.js:83-105`; `sources/Game/World/Areas/ProjectsArea.js:471`; `sources/Game/World/Areas/LabArea.js:457`, `:844`; `sources/Game/World/Areas/CareerArea.js:79-131`; `sources/Game/Game.js:166-171`; `sources/data/consoleLog.js:23-33`; `sources/index.html:838`, `:851`.
- **Depends on:** Nothing but ES module imports. Images depend on the KTX2 loader (see 2.11).
- **Transfer: DIRECT for the shape, with one change of role.** Plain typed arrays of objects are exactly what a React + TypeScript site already wants. The change: the same module must feed both the semantic HTML sections and the world, so that the world can never show content the HTML lacks. Do not copy the Career approach (content baked into textures): it makes text invisible to parsers, untranslatable and uneditable without an image tool. Keep image file names as web formats (PNG or WebP) so the same file serves an `<img>` and a texture.

### 2.2 Area lifecycle (`Area.js`, `Areas.js`, zones, references)

- **What the visitor experiences:** Driving into an area triggers things (an achievement for visiting, sounds, labels), and areas outside the camera's view stop animating and are hidden.
- **How it works:**
  - `Areas` holds a list of 13 `[name, Class]` pairs. It walks the children of one GLB scene (`areasModel`) and instantiates the class whose name is a prefix of the child's name, storing it as `areas[name]`. `EasterArea` is imported but is not in the list, so it is never instantiated.
  - The `Area` base constructor does three things. `setObjects()` registers every child of the area's GLB node as a world object (visual and/or physical, asleep by default) unless `userData.preventAutoAdd` is set, and feeds each child to a `References` parser. `setBounding()` looks for a reference named `zoneBounding`, creates a cylinder zone at its position with radius equal to its `scale.x`, and turns the zone's `enter`/`leave` events into `isIn` plus the area events `boundingIn`/`boundingOut`. `setFrustum()` looks for a reference named `zoneFrustum` and, every tick, tests whether that circle intersects the camera's visible ground quad; on change it toggles `visible` on the area's "hideable" objects and emits `frustumIn`/`frustumOut`.
  - The per-area tick runs at ticker order 10. A subclass's `update()` is called only if the area has no frustum zone or is currently in view.
  - A zone is tested every tick (order 8): for a cylinder zone the test is a 2D distance from the player to the zone centre compared with the radius, with edge-triggered `enter` and `leave` events.
  - `References.parse()` traverses an object and collects every node whose name matches `^ref(?:erence)?([^0-9]+)([0-9]+)?$` into a `Map` from the camel-cased name to an array of nodes. So `refInteractivePoint`, `referenceLetters001`, ... become `items.get('interactivePoint')`, `items.get('letters')`.
  - Subclasses then wire content in their constructors, almost always by reading references: an interactive point's position, a zone, a mesh to give a new material.
- **Evidence:** `sources/Game/World/Areas/Areas.js:23-48` (import without use at `:15`); `sources/Game/World/Areas/Area.js:9-30`, `:32-70`, `:72-102`, `:104-177`; `sources/Game/Zones.js:33-48`, `:50-81`; `sources/Game/References.js:11-31`; `readme.md` "Game loop" section (order 10 = `Area++`).
- **Depends on:** The areas GLB authored in Blender (names and `userData` are the contract), `Zones`, `Objects`, the camera's "optimal area" from `View` (other agent's slice).
- **Transfer: ADAPT.** The idea to keep is "the level file owns named anchors; code looks anchors up by name and attaches behaviour". For a 16-bit world the level would be a tile map or a small TypeScript/JSON description with named anchors (`projectsSign`, `aboutZone`, each with a position and a radius) instead of a GLB. The enter/leave zone with a 2D distance test transfers as is. View-based culling is unnecessary at this scale; a simple "is the area near the player" check is enough to skip per-area updates.

### 2.3 Landing area

- **What the visitor experiences:** The spawn area. It offers three interactive points labelled "Map", "Controls" and "Res(e)t", and a set of physical letters that make a sound when hit. **INFERRED:** the letters spell the owner's name; the look of the kiosk and bonfire cannot be checked without the GLB.
- **How it works:**
  - "Map" opens the map modal (`modals.open('map')`).
  - "Controls" opens the menu on its Controls tab and hides its own marker until that menu item closes. A listener on the Controls menu item's `open` event switches the tab to the one matching the current input device (gamepad, mouse-keyboard, or touch). Because the listener is on the menu item, it also applies when Controls is opened from the menu itself.
  - "Res(e)t" calls `game.reset()`, which respawns the player behind a transition wipe, resets every physics object, and two seconds later grants the `reset` achievement. The bonfire then shows particles and a positional fire sound.
  - Entering the bounding zone records the area as visited; leaving it grants the first achievement (`landingLeave`).
- **Evidence:** `sources/Game/World/Areas/LandingArea.js:24-38`, `:40-72`, `:74-119`, `:121-255`, `:257-267`; `sources/Game/Game.js:218-274`.
- **Depends on:** `InteractivePoints`, `Menu`, `Modals`, `Achievements`, `Audio`.
- **Transfer: ADAPT.** The useful pattern is that the spawn area is a hub for help: the map and the controls are one step away, and the first achievement is earned simply by leaving, which teaches that achievements exist. A hub with "Map" and "How to play" signs next to the Runner's start works the same way. The object-reset feature only matters in a physics sandbox.

### 2.4 Projects area

- **What the visitor experiences:** An interactive point labelled "Projects". Activating it moves the camera to a fixed framing in front of a board that shows one project at a time: a screenshot, a title, the URL, up to three attribute panels (role, at, with), award badges, pagination dots for the project's screenshots, arrows, and two signs naming the previous and next project. **INFERRED:** the surrounding scenery is a workshop (the code animates references named oven, blower, charcoal, grinder, anvil, hammer, blade).
- **How it works:**
  - **State machine:** `STATE_CLOSED → OPENING → OPEN → CLOSING → CLOSED`, with a 1.5 s `gsap.delayedCall` for each transition.
  - **Opening:** `open()` removes the `wandering` filter and adds `cinematic`; starts the camera's cinematic mode with position = point + (4.65, 4, 4.85) and target = point + (-3.0, 1.60, -4.60), tweened over 1.5 s; hides every interactive point; tweens the shade mix up (images 0.1 → 0.65, texts 0.1 → 0.3, over 2 s) so the board reads as flat bright colour; enables the mouse hit targets; deactivates the vehicle physics; shows the touch buttons `previous`, `next`, `open`, `close`; plays a click sound; records the current project in the `projects` achievement set.
  - **Paging:** `previous()` and `next()` step through the screenshots of the current project and roll over to the adjacent project at either end; the project index wraps around. They are bound to the `left`/`right` and `forward`/`backward` actions (arrow keys, WASD, gamepad d-pad), to mouse clicks on the arrow hit spheres, to clicks on pagination dots (`changeImage(index)`) and neighbour signs (`previousProject`/`nextProject`), and to the touch buttons.
  - **Changing project:** `changeProject()` updates five components, each with its own hide-then-show animation guarded by a `status === 'hiding'` flag: attributes (scale out, swap text, scale in after 1 s), adjacents (rotate out and in), title and URL (flip 180 degrees, swap text at the midpoint, finish the turn), distinctions (scale, then reposition from a table of layouts for 1, 2 or 3 badges). The text swap happens while the panel faces away, which hides the texture update.
  - **Image transition:** the board material samples an old and a new texture and wipes between them with a `step()` on UV x, with a 0.25 parallax offset, over 1 s. If the new image has not loaded, the board shows grey `#333333` and fades to the image over 1 s when it arrives (`loadProgress`).
  - **Control hints:** a "blackboard" group carries three pre-made label meshes (mouse-keyboard, Xbox, PlayStation). The one matching the input device is visible; in touch mode the whole board is removed from the scene (touch has DOM buttons instead). While the view is open the board hops every few seconds (a gsap timeline with `repeatDelay: 5`) until the visitor pages once, which sets `blackBoard.active = false`.
  - **Closing:** `close()` reverses everything; interactive points come back after 1 s. Closing is reachable through Escape, the gamepad cross button, and the touch `close` button. There is no in-world close target for the mouse, and the menu trigger is disabled while the `cinematic` filter is active.
  - **State that persists:** `navigation.index` and `images.index` live in memory, so reopening the board during the same visit resumes on the same project. Nothing about the position in the list is stored across reloads; only the set of viewed project titles is (through the achievement).
- **Evidence:** `sources/Game/World/Areas/ProjectsArea.js:14-19` (states), `:86-110` (point), `:112-174` (inputs), `:176-193` (camera offsets), `:211-223` (shade mix), `:332-545` (images), `:547-688` (pagination and arrows), `:690-765` (attributes), `:767-891` (adjacents), `:893-930` (title), `:932-1038` (URL), `:1040-1101` (distinctions), `:1113-1198` (blackboard), `:1296-1358` (open), `:1360-1414` (close), `:1416-1470` (previous/next), `:1472-1514` (changeProject), `:1516-1533` (changeImage); `sources/Game/View.js:436-459` (cinematic start/end); `sources/style/menu.styl:16-20`.
- **Depends on:** `data/projects.js`, `TextCanvas`, `RayCursor` (mouse hit tests), `Inputs` and `InteractiveButtons`, `View.cinematic`, gsap, the KTX2 loader, `Audio` groups `click`, `slide`, `assemble`.
- **Transfer: ADAPT heavily.** Worth keeping: the open/close state machine, the filter swap that freezes movement while content is open, "page within an item, then roll over to the next item", a device-specific hint that stops nagging after first use, and resuming on the last viewed item. Worth replacing: the board itself. In a portfolio whose content must stay readable, activating the "Projects" point should open the existing Projects section as a DOM dialog over the canvas (the same React component the plain page renders, with real headings, text and `<a>` links), not redraw it as textures. A cinematic camera move can still frame the Runner in front of a signboard behind the dialog for flavour. Also give pointer users a visible close control, which folio-2025 lacks in this view.

### 2.5 Lab area

- **What the visitor experiences:** The same cinematic pattern as Projects, for 13 experiments. A board shows one image, a title and a URL; beside it a vertical, endlessly looping list of thumbnails with titles scrolls on a chain. The visitor pages with keys, arrows or touch buttons, scrolls the list with the mouse wheel, or clicks a thumbnail.
- **How it works:**
  - The structure mirrors `ProjectsArea` (same states, same camera mode, same shade mix, same URL panel, same blackboard), with one image per entry instead of several.
  - **The scroller:** a template group from the GLB is cloned once per data entry. Each clone ("mini") gets its own `TextCanvas` for the title and a hit mesh. Per frame, each mini's y is `safeMod(mini.y - offset, total) - 1`, which makes the list wrap; a mini scales to zero as it passes the top (between y 3.3 and 3.9) and is hidden beyond that. Scroll position eases toward a target (`easing = 3`). Selecting an entry sets the target so the selected mini sits at a fixed slot; the mouse wheel moves the target by `value * 0.1` through an action that exists only in the `cinematic` filter. A looping sound's volume and rate follow the scroll speed.
  - **Thumbnails load lazily:** a mini requests its `imageMini` texture the first time it becomes visible, then fades in over 1 s.
  - The scroller is animated only while the board is not closed, and area updates only run while the area is in view.
  - Viewing an entry while open records its title in the `lab` achievement set.
- **Evidence:** `sources/Game/World/Areas/LabArea.js:15-20`, `:73-85` (scroll sound), `:91-112`, `:122-174`, `:334-529` (images), `:531-593` (arrows), `:595-740` (title and URL), `:742-1027` (scroller; minis `:785-963`, lazy thumbnail `:836-884`, click `:941-959`, per-frame layout `:969-1000`, wheel `:1019-1026`), `:1276-1384` (open/close), `:1406-1450` (changeProject), `:1452-1458` (update).
- **Depends on:** Same as Projects, plus the `Wheel.roll` input.
- **Transfer: ADAPT, same reasoning as Projects.** The reusable ideas are the wrapping list (position modulo total length), lazy thumbnails triggered by visibility, and a scoped wheel action that only exists while the content view is open. In a DOM dialog these become an ordinary scrollable list with `loading="lazy"` images.

### 2.6 Career area

- **What the visitor experiences:** A drive-through timeline with no interactive point. As the vehicle moves along one axis, a stone for each career entry rises beside it and a label wipes in; the stone slides along to stay next to the vehicle for as long as the vehicle is inside that entry's span. A four-digit year display follows the vehicle and counts up as it advances.
- **How it works:**
  - Each "line" is a GLB group with a `stone` child and a `careerText` mesh. Per frame, `delta = line.origin.z - player.z`. The line is "in" when `-0.25 < delta < size + 0.5`. Going in tweens `labelReveal` from 0 to 1 (1 s, after 0.3 s) and raises the stone toward elevation 2.5; the stone's z offset follows `-clamp(delta, 0, size)`. Going out lowers the stone, except that a line without `hasEnd` stays raised once the player has passed its end, which marks an ongoing position.
  - The label material discards fragments beyond `labelReveal` on UV x (a left-to-right wipe) and reads the pre-rendered texture: the red channel selects between a dark mask colour and an emissive colour chosen by `userData.color` (blue, orange, purple, green), and `max(r, g)` gives alpha.
  - The year display is four meshes driven by a 7 x 10 `DataTexture` (seven segments by ten digits). A vertex shader pushes inactive segments down. The year is `2008 + floor(offset)` with the offset clamped to 0..17, so one world unit is one year from 2008 to 2025.
  - Two positional stone-slide sounds play when a stone rises or sinks; the rising sound is pitched by the line's index.
- **Evidence:** `sources/Game/World/Areas/CareerArea.js:29-61` (sounds), `:63-149` (lines, colours `:72-77`, label shader `:106-122`), `:151-258` (year display, digit table `:175-186`, start year `:158`, size `:156`), `:268-375` (update); `sources/Game/Game.js:166-171` (the six textures).
- **Depends on:** The areas GLB, six textures authored outside the code, `Audio`.
- **Transfer: ADAPT the mechanic, SKIP the content technique.** "Position along a path is time" is a strong fit for an Experience section and for a character who runs: the Runner's progress along a track could scrub through the years, with each role appearing while the Runner is inside its span and an ongoing role staying up. The text must come from the Experience data, shown as DOM (a caption strip or a card over the canvas), not from baked images. A seven-segment year counter is trivially a pixel-font DOM element.

Activating one opens the profile in a new tab; "Discord" opens a small modal with two links instead. A ninth point labelled "OnlyFans" is a joke that drops physical fan objects, and a statue can be knocked over.

### 2.8 Achievements area (the in-world part)

- **What the visitor experiences:** An interactive point labelled "Achievements" that opens the Achievements tab of the menu. Around a pillar, small glyphs float upward in two colours, and the split between the two colours follows the visitor's completion ratio. A hidden zone behind a waterfall grants a secret achievement.

In the fragment shader, each instance picks one of two emissive colours (named "default" and "achieved" in the code) by a `step()` comparison of `instanceIndex / count` with `achievements.globalProgress.ratioUniform`. I did not work out from the shader alone which side of the comparison gets which colour. The point's interact callback opens the menu tab and hides the point; the menu item's `close` event shows it again. The secret is a second cylinder zone read from a `waterfallZone` reference.
- **Evidence:** `sources/Game/World/Areas/AchievementsArea.js:205-288` (glyphs; colour test at `:268-272`), `:290-321` (point), `:323-343` (zones).
- **Depends on:** `Achievements`, `Menu`, `Zones`.
- **Transfer: ADAPT.** The idea of a monument in the world that visibly fills in as the visitor progresses is cheap and motivating; in pixel art it could be a trophy shelf or a wall of medals with one sprite per achievement. The list itself stays a DOM panel, as it is here.

### 2.10 In-world text (`TextCanvas` and the other canvas labels)

- **What the visitor experiences:** Crisp, slightly pixelated text on boards, signs, markers and speech bubbles, in the display font.
- **How it works:**
  - `TextCanvas(fontFamily, fontWeight, fontSize, width, height, density, horizontalAlign, lineHeight)` creates an off-screen 2D canvas of `ceil(width * density)` by `ceil(height * density)` pixels, where `width` and `height` are the world-unit size of the target mesh and `density` is pixels per world unit. Projects and Lab use `density = 200`, font `'Amatic SC'` weight 700. Examples: the project title is 80 px text on an 800 x 120 canvas; an attribute panel is 46 px text on 280 x 90; a Lab thumbnail title is 36 px on 300 x 40.
  - `updateText(text)` accepts a string or an array of lines, fills the canvas black, draws the lines in white, centred vertically with `lineHeight * density` spacing, and sets `texture.needsUpdate`. Drawing happens only when the text changes, never per frame.
  - The texture uses nearest filtering, no mipmaps, sRGB, `flipY = false`. Materials read only its red channel as alpha, so colour and lighting come from the material and the canvas is a mask.
  - `getMeasure()` returns the widest line in pixels; callers divide by `density` to size a backing panel to the text (`panel.scale.x = width / density + 0.2`).
  - Three other places use the same technique with their own inline code rather than `TextCanvas`: interactive point labels (canvas height 64 px, font `700 64px "Amatic SC"`, canvas width measured from the text plus padding), the whisper speech bubble (1024 x 64 canvas, text measured and the UV range cropped to the text), and the race leaderboard board.
  - **Fonts:** Amatic SC and Nunito come from Google Fonts with `display=block`; a "Pally" family is self-hosted. A `.fonts-loader` element placed just below the viewport holds one element per font containing a space. No code waits for `document.fonts`. **INFERRED:** the element exists to make the browser fetch the fonts early so canvas text can use them; if a label were drawn before its font arrived it would keep the fallback font, because labels are drawn once.
  - Not all in-world text is live text: the Career labels, the intro control hints, the blackboard hints and the key icons are pre-made textures.
- **Evidence:** `sources/Game/TextCanvas.js:6-26`, `:28-42`, `:44-52`, `:54-64`, `:66-80`, `:82-112`; `sources/Game/World/Areas/ProjectsArea.js:254-291` (settings and mask material), `:708-717`, `:900-908`, `:942-950`, `:1022-1025`; `sources/Game/World/Areas/LabArea.js:891-904`; `sources/Game/InteractivePoints.js:212-247`; `sources/Game/World/Bubble.js:17-23`, `:235-258`; `sources/index.html:26-28`, `:56-60`; `sources/style/fonts.styl:1-46`.
- **Depends on:** The 2D canvas API, three.js textures, web fonts being loaded.
- **Transfer: ADAPT, and only for short labels.** Canvas-to-texture is the right tool for marker labels, signs and name tags in a canvas world: a pixel font, nearest filtering and an integer pixel density suit a 16-bit look. Wait for `document.fonts.ready` before drawing. It is the wrong tool for portfolio content: text in a texture cannot be selected, searched, translated, zoomed, read by a screen reader or parsed by a resume bot. Content text belongs in DOM laid over the canvas.

### 2.11 Content images in the world

- **What the visitor experiences:** Screenshots appear on the boards; a not-yet-loaded screenshot shows as a grey panel that fades to the picture.
- **How it works:**
  - Files are KTX2 containers with Basis compression, named `.ktx`, fetched through three's `KTX2Loader` (transcoder path `./basis/`). They are created offline by `scripts/compress.js`, which converts every PNG/JPG outside `ui`, `favicons` and `social` with `toktx`; with no path-specific preset, project and lab images get the default `etc1s`, quality level 255, sRGB, RGB preset. UI images (menu previews, flags, map) are converted to WebP at quality 80 with `sharp`.
  - Loading is on demand with a cache: `getResourceAndLoad(key)` returns a cached record or starts a load and stores the record in a `Map`. When the current image finishes, `loadSibling()` requests the next image in the browsing direction, crossing into the adjacent project at the ends. That is the one-ahead prefetch.
  - The first image of the first project and of the first lab entry are requested when the world is built, not when the visitor arrives, because the constructors call `changeProject(0, ...)`.
  - The code declares image sizes of 960 x 540 for boards and 240 x 135 for thumbnails, but these fields are never read. The actual file dimensions are unknown (assets not downloaded).
- **Evidence:** `sources/Game/World/Areas/ProjectsArea.js:57`, `:336-337`, `:416-432`, `:435-466`, `:469-507`, `:510-544`; `sources/Game/World/Areas/LabArea.js:56`, `:338-339`, `:435-452`, `:455-493`, `:795-796`, `:836-884`; `sources/Game/ResourcesLoader.js:27-32`; `scripts/compress.js:73-78`, `:80`, `:99-108`, `:131-145`.
- **Depends on:** `KTX2Loader` and the Basis transcoder files, a GPU.
- **Transfer: ADAPT.** Keep "load on demand, cache by key, prefetch one ahead in the direction of travel, show a placeholder that fades". Drop KTX2: a GPU texture format cannot be used by an `<img>`, so folio-2025's screenshots are unusable in HTML. For pixel-art assets and a DOM-first site, PNG or WebP serves both the `<img>` and the texture, and the browser's own lazy loading covers the DOM side.

### 2.12 External links

- **What the visitor experiences:** A project, experiment or social link opens in a new tab.

### 2.13 Interactive points (`InteractivePoints.js`)

- **What the visitor experiences:** Small diamonds float at fixed spots. Coming near one makes it grow, slides a text label out of it, shows an icon of the button to press, and plays a paper sound. Moving away folds it back. With a mouse, hovering a diamond does the same from any distance and clicking it activates it.
- **How it is defined:** `interactivePoints.create(position, text, align, state, interactCallback, revealCallback, concealCallback, hideCallback)` returns an item with `hide()`, `reveal()`, `conceal()`, `interact()` and `show()`. Every call site in the areas passes the same three small callbacks: reveal adds the touch button `interact`, conceal and hide remove it.
- **How it works:**
  - **Visuals:** a group tilted toward the camera holds a label plane and a diamond plane. The label texture is a canvas drawn once at creation. The diamond is a shader with three animated uniforms (`threshold`, `lineThickness`, `lineOffset`); the label slides with a `labelOffset` uniform that shifts UVs and discards out-of-range fragments. Both materials switch `depthTest` off while open so the label is never hidden behind scenery.
  - **States:** `STATE_HIDDEN` (nothing drawn), `STATE_CONCEALED` (small diamond, threshold 0.25), `STATE_OPEN` (diamond at 0.5, label out, key icon). Transitions are gsap tweens of 0.6 to 1.5 s with elastic and back easings.
  - **Proximity:** at ticker order 9, and only when the player has moved more than 0.2 units since the last test (or a test was requested), every item's 2D distance to the player is compared with 2.5. An item in range that is not hidden becomes the active item and is revealed; an item that fell out of range is concealed. The loop intends to pick the nearest item but never updates its `distance` variable, so among several items in range the last one created wins.
  - **Per-device label:** a single shared key-icon mesh is re-parented to whichever point is open. Its texture is an Enter-key icon for mouse-keyboard, an "A" for an Xbox pad, a cross for other pads, swapped on the inputs' `modeChange` event and the gamepad's `typeChange` event. In touch mode the icon is hidden.
  - **Activation routes:** (1) the `interact` action, bound to Enter, E, F and gamepad cross, calls `activeItem.interact()` when the active item is open; (2) the DOM touch button named `interact` does the same, and its container is displayed only while the input mode is touch; (3) each point registers a sphere of radius 0.75 with `RayCursor`; hovering it makes it the active item and reveals it, leaving conceals it, and a click (pointer up after less than 25 px of total drag) calls `interact()` as long as the point is not hidden. The ray test only considers targets within the camera's visible radius, and it sets `cursor: pointer` on the canvas while anything is hovered. A tap on the marker goes through the same ray route.
  - **Coordination with content views:** `temporaryHide()` stores each item's state and hides all of them (used when Projects or Lab opens); `recover()` shows them again. Points start hidden and appear when the intro finishes, through the same `recover()`. A point that opens a DOM panel hides itself and comes back on that panel's `close` event.
  - **What it is not:** there is no DOM element per point. Points cannot receive keyboard focus, are not in the accessibility tree, and cannot be reached with Tab.
- **Evidence:** `sources/Game/InteractivePoints.js:9-14` (constants), `:46-63` (sounds), `:95-159` (key icon), `:161-178` (inputs), `:180-203` (signature and group), `:212-247` (label canvas), `:253-288`, `:294-329` (diamond), `:334-344` (item), `:349-384` (ray target), `:390-422` (hide), `:425-465` (reveal), `:468-512` (conceal), `:515-525` (interact), `:528-536` (show), `:576-641` (proximity; thresholds at `:585` and `:595`; the stale `distance` at `:590-602`), `:643-663` (temporary hide and recover); `sources/Game/Player.js:237` (key bindings); `sources/Game/Inputs/InteractiveButtons.js:16-37`, `:98-114`; `sources/Game/Inputs/Inputs.js:310-313`; `sources/Game/RayCursor.js:73-89`, `:142-150`, `:173-190`; `sources/Game/Reveal.js:213`; `sources/Game/World/Areas/LandingArea.js:86`, `:105-108`.
- **Depends on:** `Inputs`, `InteractiveButtons`, `RayCursor`, `Player` position, gsap, three key-icon textures, `Audio`.
- **Transfer: ADAPT; this is the central piece to borrow.** Keep: one factory, three states, a proximity radius, one shared "press this" hint that changes with the input device, activation by key, pad, click and touch button, hide-all and recover-all around content views, and "the point hides while its panel is open". Change: give every point a DOM counterpart. The simplest robust form is a visually hidden list of real `<button>` or `<a>` elements ("Go to Projects", "Open Contact") that mirrors the points, so keyboard and assistive-technology users can activate the same callbacks without steering. Also fix the nearest-item selection, and replace the eight-argument positional signature with an options object.

### 2.14 Input modes, input filters and touch buttons (as far as the interface needs them)

- **What the visitor experiences:** Hints and buttons change when the visitor switches from keyboard to gamepad to touch. While a panel is open the vehicle does not respond.
- **How it works:**
  - **Mode:** `Inputs.mode` is one of mouse-keyboard, gamepad or touch, updated by whichever device produced the last event. A change swaps a class on `<html>` (`is-mode-mouse-keyboard`, `is-mode-gamepad`, `is-mode-touch`), shows or hides the touch button container, and emits `modeChange`. The gamepad class adds `is-gamepad-default`, `is-gamepad-xbox` or `is-gamepad-playstation` from a regular expression on the pad's id string.
  - **Actions and filters:** an action is `{ name, categories, keys }`. `start()` and `change()` only fire an action if `checkCategory()` passes: the filter set is empty, or the action has no categories, or one of its categories is in the set. `end()` is not filtered, so a key released after the context changed still releases its action. The filter set is an observable `Set` mirrored as `input-filter-<name>` classes on `<html>`.
  - **Text fields:** the keyboard listener ignores every key except Escape while focus is in an `input`, `textarea` or `contenteditable` element.
  - **Touch buttons:** six `<button>` elements exist in the HTML (`interact`, `unstuck`, `previous`, `next`, `open`, `close`). Code adds or removes names from a set; the class shows the matching buttons and a gradient backdrop when any is visible. A click emits an event with the button's name.
  - **No consumed flag:** when one physical button is bound to two actions, both fire in the same call. The gamepad cross button is bound to `interact` and to `close`. `ClosingManager` has an explicit guard for the menu (in gamepad mode it does not close a menu that is still opening). **INFERRED:** Projects and Lab have no such guard, so on a gamepad the press that opens the board would also reach the close branch and close it at once. I did not run it; see section 4.
- **Evidence:** `sources/Game/Inputs/Inputs.js:13-15`, `:23-40`, `:60`, `:169-181`, `:183-202`, `:204-236`, `:238-259`, `:302-326`; `sources/Game/Inputs/Gamepad.js:204-208`, `:300-314`; `sources/Game/Inputs/Keyboard.js:21-29`; `sources/Game/Inputs/InteractiveButtons.js:16-96`; `sources/index.html:67-77`; `sources/style/interactiveButtons.styl:1-28`, `:48-58`; `sources/Game/Player.js:221-238`; `sources/Game/ClosingManager.js:16`, `:38`, `:46-47`.
- **Depends on:** DOM events, the Gamepad API.
- **Transfer: DIRECT.** A filter set plus categories on actions is a small, sufficient answer to "which keys work right now", and it is far easier to reason about than scattered `if (menuOpen) return` checks. Mirroring mode and context onto the root element (as classes or `data-` attributes) lets Tailwind variants style the hints with no extra state plumbing. Add what is missing: an action should be able to mark an input as consumed.

### 2.15 Menu (`Menu.js`)

- **What the visitor experiences:** A button at the top right opens a panel centred over the dimmed world: a picture on one half, content on the other, and a row of seven icon tabs above (home, options, controls, achievements, circuit, whispers, behind the scene). Escape also opens it.
- **How it works:**
  - **Markup:** all seven content blocks and seven preview images are in `index.html` from the start. Each navigation button carries `data-name`; the class pairs it with `.<name>-preview` and `.<name>-content`.
  - **Opening:** `open(name)` defaults to the last opened item, or the first one. It plays a click sound, swaps `is-active`/`is-visible` classes, focuses the item's `.js-main-focus` element if there is one and the mode is not touch (only the whisper text input has that class), sets the input filters to exactly `{menu}`, emits `open` on the menu and on the item, then adds `is-displayed` and, two animation frames later, `is-visible` to run a 0.3 s opacity transition. The state goes `OPENING → OPEN` on `transitionend`.
  - **Closing:** `close()` removes `is-visible`, sets `CLOSING`, emits `close`; `transitionend` sets `CLOSED` and removes `is-displayed`. Close is triggered by the close button, by a click on the backdrop itself, and by `ClosingManager`.
  - **Entry points:** the trigger button; Escape when nothing else is open; the gamepad Start button (toggles, opening on `home`); interactive points (Controls, Achievements, Behind the scene); the T key (whispers); clicking an achievement toast; during a race the trigger and Escape open the `circuit` tab instead.
  - **Gamepad:** R1 and L1 cycle through the tabs, as actions that exist only in the `menu` filter.
  - **Per-item events:** each item has its own emitter (`open`, `opened`, `close`, `closed`), which is how other classes react to "my tab was shown".
  - **Trigger visibility:** CSS slides the trigger out of view and disables its pointer events whenever the `menu`, `modal`, `cinematic` or `intro` filter class is present. The trigger is `display: none` until JavaScript adds `is-started` to `<html>`.
  - **Keyboard quirk:** the trigger button cancels every `keydown` it receives. **INFERRED:** this stops Space or Enter (game keys) from re-activating the button after a mouse click, and it also means a keyboard user cannot activate it or Tab away from it.
  - **Layout:** the panel is `min(1000px, 100% - 120px)` by `min(600px, 100% - 120px)`. In portrait orientation the two halves stack (picture 30 percent, content 70 percent) and the panel narrows to `min(600px, 100% - 20px)`. Further breakpoints at 870, 520, 440 and 360 px shrink padding and buttons.
  - **Missing:** no `role="dialog"`, no focus trap, no return of focus on close, no `inert` on the rest of the page. The world keeps simulating behind the menu; nothing is paused.
  - `preopen()` would open any item whose button carries `data-preopen` once the intro ends; no element uses it at HEAD.
- **Evidence:** `sources/Game/Menu.js:9-12`, `:35-51`, `:53-70`, `:72-90`, `:92-144`, `:146-169`, `:171-254`, `:256-272`, `:274-284`; `sources/index.html:80-90`, `:102-739`; `sources/style/menu.styl:1-20`, `:43-48`, `:94-124`, `:126-133`, `:138-148`, `:188-236`; `sources/Game/Game.js:75`; `sources/Game/ClosingManager.js:54-55`, `:60-73`.

- **Transfer: ADAPT.** The structure (one overlay, named items, per-item open and close events, any world object can call `menu.open('name')`) maps directly onto a React dialog with a tab state and a small event or store API. The implementation should use a real dialog: `role="dialog"` or `<dialog>`, a focus trap, focus restore, Escape handling, and the canvas marked inert. framer-motion's presence handling replaces the hand-written `OPENING`/`CLOSING` states and `transitionend` listeners. Keep the "content half plus picture half, stacked in portrait" layout idea if it suits the pixel-art frame.

### 2.18 Options (`Options.js`)

- **What the visitor experiences:** Six rows: Audio (toggle), Quality (toggles "High"/"Low"), "I'm stuck!" (Respawn), Reset, Renderer (a read-only badge: WebGPU or WebGL), Server (a read-only badge: Pending, Online or Offline). Each control has a hover tooltip.

### 2.19 ClosingManager (Escape and back)

- **What the visitor experiences:** Escape always does the sensible thing: it closes the innermost open thing, or opens the menu if nothing is open. On a gamepad the cross button closes and Start toggles the menu.
- **How it works:** The class registers a `close` action (Escape, gamepad cross) and a `pause` action (gamepad Start), both valid in the `modal`, `menu`, `racing`, `cinematic` and `wandering` filters. On `close` it tests, in order: the whisper flag picker; the race flag picker; an open modal; an open menu (or an opening one unless the mode is gamepad); a running race (opens the `circuit` menu tab as a pause screen); an open or opening Projects view; an open or opening Lab view; and finally, only if the key was Escape, it opens the menu. ### 2.20 Notifications (`Notifications.js`)

- **What the visitor experiences:** A toast drops in at the top centre, shows a shrinking time bar, and leaves. Hovering it holds the timer. Clicking it dismisses it, and for an achievement toast also opens the Achievements tab.

When the rounded offset changes (and at most once per 1/60 s) it rebuilds a 30-character strip with the car at index 10 and a tree every 18 characters, nudges overlapping items apart, and assigns `document.title = 'Bruno' + strip`.

### 2.22 Overlay (transition wipe)

- **What the visitor experiences:** A dark patterned wipe sweeps diagonally across the picture whenever the player is teleported (respawn, fast travel from the map, reset, race start and end), with a swoosh sound, then sweeps away.
- **How it works:** Despite its name it is not a DOM overlay. It is a full-screen quad inside the 3D scene (render order 99, no depth test) whose shader discards fragments by comparing a `progress` uniform with a tiled pattern plus a diagonal gradient. `show(callback)` tweens progress to 1 in 2 s and then calls back; `hide()` tweens to 0 in 4 s with the pattern inverted. `Player.respawn()` uses it as: show, teleport inside the callback, hide. Because it is in the canvas it does not cover the DOM interface.
- **Evidence:** `sources/Game/Overlay.js:14-71`, `:95-112`, `:114-137`; `sources/Game/Player.js:469-488`.
- **Depends on:** gsap, a pattern texture, `Audio`.
- **Transfer: DIRECT as a pattern.** "Cover, change the world, uncover" hides teleports and loading hitches. In a 16-bit style this is a classic iris or checkerboard wipe, drawn in the canvas or as a CSS mask over it. Offer an instant cut when reduced motion is requested.

### 2.23 Map and fast travel (`Map.js`)

- **What the visitor experiences:** A square map opens from the second corner button, from the M key, or from the "Map" point at the spawn. It shows a picture of the island, twelve labelled pins, and an arrow for the player that moves and turns live. Clicking a pin teleports the player there behind the wipe.
- **How it works:**
  - **Rendering:** not a live render. The background is one of two pre-made images (`ui/map/map-day.webp`, `ui/map/map-night.webp`), chosen each time the map opens from the day cycle's `night` interval. The `<img>` has no `src` until the first open, and fades in on `load`.
  - **Pins:** a hard-coded list of twelve `{ name, respawnName, offset }`. For each, the respawn point's world position is converted to map space as `position / terrain.size + 0.5`, clamped to 0..1, then used as CSS `left`/`top` percentages plus a hand-tuned label offset. Pins are plain `div`s with `z-index` from their y so lower pins overlap higher ones. Names scale in on hover and are always shown in touch mode.
  - **Fast travel:** a pin's click handler calls `player.respawn(respawnName)` and closes the modal.
  - **Player marker:** while the modal is open, each tick (order 14) the marker's percentages and rotation are updated, but only when the player's rounded position changed.
  - **Lazy:** pins, marker and tick listener are created on the first open.
  - **Sizes:** 1024 px square, 768 below 1100 px wide, 512 below 800 px, never larger than `100vmin`.
  - The Toilet area is absent from the pin list, so the map shows 12 of the 13 areas.
  - Pins are `div`s with click listeners: not focusable, no keyboard route.
- **Evidence:** `sources/Game/Map.js:17-23`, `:26-38`, `:40-89` (pin list `:43-56`, click `:80-87`), `:98-120`, `:122-134`, `:136-152`, `:154-169`, `:171-192`; `sources/index.html:93-99`, `:863-878`; `sources/style/map.styl:77-95`, `:263-282`; `sources/Game/Respawns.js:14-38`.

- **Transfer: DIRECT, and static-friendly.** A map made of one image plus DOM pins placed by percentage needs no rendering work and no backend. For a tile-based world the image can be generated from the level data at build time. Make the pins real `<button>` elements: then the map doubles as an accessible table of contents and as the keyboard route to every section ("jump to Projects"), which solves much of the reachability problem of a free-roam world.

### 2.24 Loading and onboarding (`Intro.js`, `Reveal.js`, `Game.js`, `index.html`)

- **What the visitor experiences:** A dark page; then a small patch of ground with a thin ring that fills clockwise while everything loads; then a hint showing the controls for the visitor's device and a sound on/off button; then, after a click or key press, the world unfolds outward from the ring, the camera pulls in on the vehicle, sound starts, and markers pop up.
- **How it works:**
  - **Before JavaScript:** `index.html` has no loader element and no text for this phase. The only visible thing is the page background gradient.
  - **Boot, batch 1:** `Game.init()` adds `is-started` to `<html>`, creates the input system with the `intro` filter, awaits the renderer, then awaits four small resources (respawn points, two textures for the intro, the colour palette). Four `<link rel="preload">` tags in the head target the same four files.
  - **Step 0 of the world:** only a grid and the `Intro` object exist. The intro places a ring (radius 3.5, thickness 0.04) at the default respawn point. Its shader discards fragments whose angle is beyond a progress uniform.
  - **Batch 2:** 40 resources plus the physics WebAssembly module load in parallel. The loader's callback gives `toLoad` and `total`, and `intro.updateProgress(1 - toLoad / total)` sets the target; each tick the displayed value eases toward it (`+= (target - current) * delta * 10`). Progress is a count of finished files, not bytes. There is no percentage text.
  - **Build:** when both promises resolve, the rest of the game is constructed in one go, then three frames later `reveal.updateStep(0)` runs.
  - **Reveal step 0 (ready):** the ring shrinks away (1.5 s); a "reveal distance" uniform grows to 3.5 so only a disc of world around the spawn is drawn; the camera zooms; the hint label and the sound button are created and scale in after about a second. The hint is a pre-made texture chosen by input mode and pad brand (`intro/<mouseKeyboard|gamepadXbox|gamepadPlaystation|touch>Label.ktx`), loaded on demand and swapped if the device changes. The sound button is a two-frame sprite that toggles mute through the ray cursor.
  - **The start gesture:** a click or tap inside a sphere of radius 3.5 at the spawn (hover brightens the ring by a factor of 1.22), or the `introStart` action: Enter, Arrow Up, Arrow Down, W, D, or gamepad cross. With `#skip` in the URL hash the step is taken automatically and the intro animations run four times faster.
  - **Reveal step 1 (start):** `audio.init()` is called here, inside the first user gesture, which is what satisfies browser autoplay rules. The reveal distance grows to 30 over 2 s and is then set to 99999; the hint hides; the filters become `{wandering}`, which is the moment the controls come alive; the camera starts tracking the player.
  - **Reveal step 2 (settled):** interactive points are recovered (they appear), the whispers are created, the intro objects are destroyed, the WebSocket connection is started (not earlier), and `menu.preopen()` runs.
  - **How controls are taught:** five places. The intro hint image; the "Controls" point beside the spawn; the Controls tab of the menu; the key icon on every interactive point; and the blackboards inside Projects and Lab.
  - **Spawn:** always the respawn point named by `VITE_PLAYER_SPAWN`, or `landing` by default; the height is forced to 4, so the vehicle drops in.
  - **Failure:** there is no `try`/`catch` and no error element anywhere in `sources/`. A failed resource rejects the loader's promise. **INFERRED:** the ring then simply stops filling and nothing else happens.
- **Evidence:** `sources/index.html:39-42`, `:54-64`; `sources/style/general.styl:48-51`; `sources/Game/Game.js:75`, `:87`, `:95`, `:102-109`, `:111`, `:129-181`, `:185-209`; `sources/Game/World/World.js:47-86`; `sources/Game/World/Intro.js:23-49`, `:51-114`, `:116-200` (file name at `:153`), `:202-259`, `:261-304`, `:306-314`; `sources/Game/Reveal.js:46-148` (skip at `:48`, `:100-103`; gesture at `:124-145`), `:149-210` (audio at `:152`, filters at `:174-175`), `:211-227`; `sources/Game/ResourcesLoader.js:55-123`; `sources/Game/Respawns.js:26-34`.
- **Depends on:** `ResourcesLoader`, `RayCursor`, `Inputs`, `Audio`, gsap, the materials' reveal uniform (other agent's slice).
- **Transfer: ADAPT.** Strong ideas: the loading indicator lives in the world's own visual language; "ready" and "start" are separate, and the single start gesture does three jobs (consent to begin, audio unlock, enabling input); the hint matches the device; heavy and optional things (the socket, extra subsystems) start only after the visitor is in. Changes for an opt-in world on a static site: the world must load only after the visitor chooses it (a dynamic `import()` behind an "Explore" button), so the plain page costs nothing extra; that button click is already a user gesture, so it can serve as the audio unlock; show a DOM progress indicator with text so the state is announced to assistive technology; write the hints as text over the canvas rather than as images; and provide an error state with a way back to the page.

### 2.25 Persistence between visits

- **What the visitor experiences:** Achievements, the chosen vehicle paint, mute, play time, distance driven and the chosen flag are remembered. Position, quality, the last viewed project and the open menu tab are not.
- **How it works:** Everything is `localStorage` with flat string keys, read once at construction and written on change:
  - `uuid`: a random v4 id created on first visit and sent with every server message.
  - `soundToggle`: `'1'` when muted, `'0'` otherwise.
  - `achievements`: one JSON object from group name to a number, or to an array for `Set`-based groups.
  - `achievementsTimeStart`, `achievementsTimeEnd`: play-time stamps for the completion time.
  - `achievementsReward`: the name of the active reward.
  - `timePlayed`: cumulative seconds, written every second by `setInterval`.
  - `distanceDriven`: metres, written whenever the floored value changes.
  - `countryCode`: the chosen flag; when absent the picker guesses from the locale reported by `Intl.DateTimeFormat`.
  - One cookie, `acceptedCookies=<n>`, belongs to a joke area that counts "accepted cookies".
  - There is no versioning or migration of the stored data, and no guard around storage access.
- **Evidence:** `sources/Game/Server.js:13-18`; `sources/Game/Audio.js:659`, `:671`, `:677-679`; `sources/Game/Achievements.js:46-75`, `:95-111`, `:137-141`, `:160-161`, `:211-217`, `:242`; `sources/Game/Player.js:333-341`, `:457-466`, `:659-666`; `sources/Game/InputFlag.js:48-67`, `:201`, `:209`; `sources/Game/World/Areas/CookieArea.js:259-266`, `:497`.
- **Depends on:** `localStorage`, `document.cookie`.
- **Transfer: DIRECT, plus three safeguards.** `localStorage` is the whole persistence story for a static site. Wrap access in `try`/`catch` (storage can throw when blocked), put a version number in the stored object, and namespace the keys, because every project on the same GitHub Pages user domain shares one origin and therefore one `localStorage`.

### 2.26 Audio (`Audio.js`)

- **What the visitor experiences:** Music, a bed of ambience that follows time of day and weather, sounds that come from places in the world and fade with distance, and short interface sounds. One switch mutes everything, and the choice is remembered. Leaving the tab silences the page.
- **How it works:**
  - **Setup:** every sound is a Howler `Howl` created by `audio.register(options)`. Defaults: volume 0.5, `pool: 2`, `preload: true`, an anti-spam interval of 0.1 s. The item returned has `play(...params)`, plus mutable `volume`, `rate` and `positions`. No `html5` flag is used anywhere, so every sound, music included, is fully fetched and decoded by Web Audio rather than streamed. The source references 81 distinct mp3 paths across 58 register call sites.
  - **Groups:** an item may name a `group` (default `all`). A group offers `play()` (round robin: the item after the last one played) and `playRandomNext()` (a random other item). Hit sounds use the random form so repeats do not sound identical. Other classes fetch shared sounds by group name, for example `audio.groups.get('click').play(isOpen)`.
  - **Two hooks:** `onPlay(item, ...params)` runs just before a play and usually randomises volume and rate or copies an emitter position. `onPlaying(item)` runs every frame and binds volume or rate to live state: rain volume to the rain amount, wind to wind strength, wave volume to the distance from the map edge, the scroll sound to the scroll speed.
  - **Autoplay unlock:** before `audio.init()` runs, `item.play()` returns immediately. `init()` is called from the start gesture; it builds the playlist, the ambiences and the one-shot groups, then starts every item registered with `autoplay: true` that could not start earlier.
  - **Music:** a playlist of three tracks, each a `Howl` with `preload: false`, `pool: 0`, volume 0.2, no loop. The starting index is `floor(Date.now() / 1000 / 60 / 3) % 3`, so it changes every three minutes of wall-clock time. On `end`, `next()` plays a "disc change" sound, waits 3 s, advances, plays, and shows a "Now playing" toast. Music plays only if the build flag `VITE_MUSIC` is set.
  - **Ambience:** bird calls on a random timer by day, an owl at night, a rooster at dawn, a wolf at deep night, crickets that fade in over 15 s at night, bells tied to snow, plus loops for rain, wind, waves and fires. One-shot animal sounds are given a random position offset by 30 units on both ground axes from the camera's focus point, so they always come from a diagonal.
  - **Positional audio:** done by hand each frame (ticker order 14). For an item with `positions`, the position nearest to the camera's focus point is chosen, transformed into camera space, normalised, its depth scaled by 0.1, and passed to `howl.pos(x, y, z)`. If `distanceFade` is set, volume is multiplied by a linear ramp from 1 at distance 0 to 0 at that distance. An item may have several positions (one fire sound serves two fires).
  - **Per-frame housekeeping:** for every item, rate is set to `clamp(item.rate * globalRate, 0.5, 4)` where `globalRate` follows the game's time scale (slow motion lowers pitch), volume is applied, and the item is muted when its volume is below 0.01.
  - **Mute:** `Howler.mute(true/false)`, a root class `is-audio-muted`, a `muteChange` event, the `soundToggle` storage key, a keyboard action on the `l` key valid in every filter, a button in Options and a button on the intro screen.
  - **Tab hidden:** not `visibilitychange`. On window `blur` everything is muted and the current track is paused; on `focus` it is unmuted and resumed unless the visitor had muted.
- **Evidence:** `sources/Game/Audio.js:26-43` (init), `:45-145` (register; defaults `:75-103`; play `:106-140`), `:56-70` (group play), `:147-255` (playlist; index `:164`; Howl options `:172-183`; next `:186-237`; flag `:251-254`), `:257-510` (ambience; random direction `:259-266`), `:512-636` (one-shots; click pitch `:529-538`), `:638-711` (mute; storage `:659`, `:671`, `:677-679`; key `:682-689`; blur and focus `:692-709`), `:713-768` (update; positional `:727-756`; rate `:759`; mute threshold `:765`); `sources/Game/Reveal.js:152`; `sources/Game/World/Intro.js:202-259`.
- **Depends on:** `howler`, `Ticker`, `View` (camera matrix and focus point), `DayCycles`, `Weather`, `Notifications`, the mp3 files.
- **Transfer to a purely synthesised Web Audio setup:**
  - **DIRECT:** the registry and group API; the anti-spam interval; the `onPlay` hook (randomise pitch and gain per trigger, which matters even more for synthesised blips); the `onPlaying` hook (bind a gain or filter cutoff to game state each frame); one click sound played at two pitches for open and close; creating or resuming the `AudioContext` inside the start gesture; the persisted mute with a root attribute for CSS; muting when the page loses focus.
  - **ADAPT:** positional audio becomes a `StereoPannerNode` driven by the emitter's camera-relative x plus the same linear distance gain; a full 3D panner is unnecessary for a 16-bit look. The playlist becomes a set of sequencer patterns, with the "Now playing" toast optional. Use `visibilitychange` with `AudioContext.suspend()` and `resume()` rather than blur and focus, which fire on mere clicks into developer tools or an iframe. The below-threshold mute becomes "do not start the voice at all".
  - **SKIP:** Howler itself, pools, preload management, and the 81 files. Do not reuse any of the sounds or music.
  - **Add:** a volume control and separate music and effects switches, both absent here.

### 2.27 Achievements (`Achievements.js` and `data/achievements.js`)

- **What the visitor experiences:** Doing things for the first time (leaving the start area, viewing every project, flipping the car, finding a secret) pops a toast with confetti and a jingle. The Achievements tab lists all of them with progress bars, shows "n / 38", offers six vehicle paints that unlock as the count rises, and has a reset button.
- **How it works:**
  - **Definition:** 38 tuples in 33 groups. A group is a named counter shared by all entries that use its name, which gives tiers for free: the `cookie` group has entries at 1, 10, 100 and 1000, `distanceDriven` at 1, 10 and 100 km. Four groups are flagged unique (`areas`, `projects`, `lab`, `explosiveCrates`); their progress is a `Set` of ids and counts distinct things, so visiting the same area twice does not count twice. The data has no category field. Sorted by subject (my own grouping, from reading each entry): 4 for exploring and reading content (leave the start, visit all 13 areas, view every project, view every lab entry); 10 for driving and stunts (two flips, ending upside down, the hydraulics, height, three distance tiers, the horn, driving into the sea); 13 for world interactions and mini-games (four cookie tiers, the crates, a bowling strike, two for finishing a race, two for toppling things, the altar, spawning a fan, the reset); 4 for time and weather (staying a full day cycle, snow, rain, lightning); 3 that need the server (posting a whisper, entering the leaderboard, witnessing the shared event); 4 secrets and meta entries (the hidden zone, the Konami code, debug mode, and the one that cannot be earned).
  - **Triggers:** code anywhere calls `achievements.setProgress(group, value)` or `addProgress(group)`. For a `Set` group the value is an id (an area name, a project title, a crate id). There are about 45 call sites, in area classes, the player, and the weather effects. One entry (`hacker`) has no trigger in the code at all; its description says it cannot be achieved. One (`debug`) is granted by loading the page with `#debug`.
  - **Engine:** `group.setProgress()` adds to the set or stores the number, and if the size or number changed calls `updateItems()`, which updates each entry's text and bar and calls `achieve()` on any entry whose total is reached.
  - **Reward loop:** `achieve()` (when not silent) updates the global count and the rewards, pops confetti at three spots around the player, plays a sound with a 0.5 s anti-spam, and shows a 4 s toast whose click opens the Achievements tab.
  - **Unlocks:** six reward buttons in the HTML, each with threshold `round(i / 5 * total)`. **INFERRED** from that formula and 38 entries: 0, 8, 15, 23, 30 and 38. Choosing an unlocked reward emits `rewardActiveChange`, which the vehicle uses to swap its paint material, and stores the choice. The last threshold equals the total, which includes the untriggerable entry and several that need the server.
  - **Completion time:** when every entry is achieved, the play-time stamp is stored and the tab shows how long it took.
  - **Persistence:** one JSON blob under `achievements`, saved after every change; on load each stored value is replayed through `setProgress(value, silent = true)` so nothing pops.
  - **Reset:** the button needs three clicks ("Are you sure?", "Definitely?", "Done!") and resets its count on `mouseleave`. `reset()` clears every group, the distance counter and the time stamps, then re-grants what is already true (the player is outside the start area; debug mode is on).
  - **List rendering:** the tab's list is built with `innerHTML` from the tuples at start-up; descriptions contain `<strong>` tags.
- **Evidence:** `sources/data/achievements.js:6-237` (unique flags at `:17`, `:24`, `:31`, `:104`; `hacker` at `:232-237`); `sources/Game/Achievements.js:25-39` (load), `:42-76` (storage), `:78-167` (global progress), `:169-289` (rewards; threshold `:184`; set `:221-248`), `:291-306`, `:308-392` (group engine), `:394-482` (list and `achieve`; confetti `:444-449`; toast `:470-478`), `:511-547` (reset button), `:549-577`, `:579-614`; `sources/index.html:511-575`; `sources/Game/World/VisualVehicle.js:224-246`; `sources/Game/Game.js:212-215`; trigger examples `sources/Game/World/Areas/LandingArea.js:259-266`, `sources/Game/World/Areas/ProjectsArea.js:1357`, `:1513`, `sources/Game/Player.js:639-673`.
- **Depends on:** `Menu` (the tab), `Notifications`, `Audio`, the confetti effect, `localStorage`.
- **Transfer: DIRECT.** Nothing needs a server. The tuple-plus-group model is compact and covers "do X once", "do X n times" and "do all of these distinct things". For a portfolio the natural entries are content-driven: visit every section, open every project, find the secrets. The natural reward for a pixel sprite is a palette swap. Three cautions: never gate portfolio content behind an achievement; make every entry attainable on a static host (folio-2025's full completion is not, without its server); and announce unlocks through a live region.

### 2.28 Server-backed features (`Server.js`, `Whispers.js`, `Bubble.js`, the leaderboard, counters, flags)

- **What the visitor experiences:** Flames dotted around the world; driving near one shows a speech bubble with a short message and a flag left by another visitor. The visitor can leave one too. A race track has a top-ten board that resets daily. Two counters in the world are shared by everyone. Occasionally a tornado appears for everyone at once. An Options badge says whether the server is online.
- **How it works:**
  - **Transport:** a native `WebSocket` to `VITE_SERVER_URL` with `binaryType = 'arraybuffer'`. Messages are plain objects encoded with `msgpack-lite`. Every outgoing message has the stored `uuid` merged in. `start()` is called only after the intro finishes; it does nothing when the URL is empty, and otherwise retries `connect()` every 2000 ms while disconnected. The first message received is kept as `initData` so that subsystems created later can read it.
  - **Client to server messages:** `whispersInsert { message, countryCode, x, y, z }`; `circuitInsert { countryCode, tag, duration, checkpointTimings }`; `cataclysmInsert {}`; `cookiesInsert { amount }` (accumulated and flushed once per second).
  - **Server to client messages:** `init` (carrying `whispers`, `circuitResetTime`, `circuitLeaderboard`, `cataclysmCount`, `cataclysmProgress`, `cataclysmRunning`, `cookiesCount`, `easterEggs`); `whispersInsert { whispers }`; `whispersDelete { whispers }`; `circuitUpdate { circuitLeaderboard }`; `cataclysmUpdate`; `cookiesUpdate { cookiesCount }`; `easterUpdate { easterEggs }`. A leaderboard row is an array `[tag, countryCode, durationMs]`. A whisper is `{ id, message, countrycode, x, y, z }`.
  - **Whispers in the world:** one instanced mesh of `VITE_WHISPERS_COUNT` (30) flame planes with a per-instance reveal value. Insert, update and delete each tween that value. Each tick the nearest whisper to the player is found; within 3 units a single shared `Bubble` object shows its message and flag. The bubble hides, swaps text and reappears when the nearest whisper changes.
  - **Posting:** the T key or the Whispers menu tab. The form has a flag picker, a text input (`maxlength="30"`) and a submit button, with a live preview on the picture half that is itself `contenteditable`. The client trims, strips emoji with `emoji-regex` and cuts to 30 characters (the code reuses the whisper count as the character limit). Submit is enabled only while connected. The message is sent with the player's current position, so the flame appears where the visitor stood. The HTML states the rules: everyone sees them, new ones replace old ones (max 30), one per user, no slurs, 30 characters.
  - **Flag picker (`InputFlag`):** a searchable list built from `data/countries.js`, added to the DOM only on first open, with the choice stored in `localStorage` and the default guessed from the locale. Used by the whisper form and the race form.
  - **Leaderboard:** shown twice, on an in-world canvas texture and as an HTML table in the Circuit menu tab, with a "Resets in ..." countdown computed from `circuitResetTime`. After a race, the end modal opens only if connected, and offers the three-letter name form only if the time would enter the top ten.
  - **What the server stores (INFERRED from the messages; the server is closed source):** up to 30 whispers keyed to a user id, a daily top ten, two global counters, the state of a shared world event, and promo "egg" usage counts. `checkpointTimings` is presumably there for plausibility checks. Any moderation ("No slur!") must happen server-side, since the client only strips emoji.
  - **When the server is unreachable:** `<html>` carries `is-server-offline` from the start. CSS shows every `.offline-element` (warning lines) and hides every `.online-element` (the table, the form). The Options badge reads "Offline / Should be back soon". The whisper submit stays disabled; the in-world board reads "OFFLINE"; the altar counter reads "..."; no flames exist. A toast announces disconnection, and reconnection if the session is older than 10 s. Everything else works; the credits text says so.
- **Evidence:** `sources/Game/Server.js:13-24`, `:26-40`, `:42-103`, `:105-122`, `:124-132`; `sources/Game/World/Whispers.js:16`, `:53-98`, `:100-265` (message types `:240-257`), `:267-273`, `:275-425` (sanitise `:287-300`, submit `:302-330`), `:427-438`, `:440-528`; `sources/Game/World/Bubble.js:17-35`, `:138-165`, `:167-233`, `:235-283`; `sources/Game/InputFlag.js:48-79`, `:81-106`, `:108-153`, `:155-181`, `:193-216`; `sources/Game/World/Areas/CircuitArea.js:857-959`, `:1146-1205`, `:1283-1304`, `:1466-1500`, `:1606-1618`; `sources/style/circuit-end.styl:18-35`; `sources/Game/World/Areas/AltarArea.js:38-45`, `:417-445`; `sources/Game/World/Areas/CookieArea.js:406-451`; `sources/Game/Tornado.js:116-141`; `sources/Game/Options.js:80-117`; `sources/style/general.styl:386-390`; `sources/index.html:582-584`, `:628-679`, `:710`; `.env.example`.
- **Depends on:** A WebSocket server that is not in the repository, `msgpack-lite`, `uuid`, `emoji-regex`, `Menu`, `Modals`, `Notifications`.
- **Transfer: SKIP. These are impossible on a static host without a backend:** visitor messages visible to other visitors, a shared leaderboard, shared counters, a world event triggered for everyone, promo codes controlled from the server, and an online/offline indicator. There is no static substitute for shared, moderated, user-written state. What does transfer:
  - Local analogues: a personal best time, or a personal "ghost" run, in `localStorage`.

### 2.29 Easter eggs and seasonal events

- **What the visitor experiences and how each is triggered:**
  - **Konami code:** a `keydown` listener on `document` compares `event.code` against Up, Up, Down, Down, Left, Right, Left, Right, B, A. Each step accepts the arrow key or its WASD equivalent, and the final step accepts `KeyA` or `KeyQ` (the physical position of "A" on a French keyboard). A wrong key resets the sequence. On success it loads an alternative vehicle model on demand, replaces the vehicle's visuals, pops confetti and grants an achievement; entering it again toggles back.
  - **Console banner:** when the build flag `VITE_LOG` is set, the entry file logs an ASCII banner with a greeting, all social links and the e-mail address, how to enable debug mode, credits and source links. The text is split into `%c` segments so the box-drawing characters are purple and the text white.

### 2.30 Accessibility, SEO and fallback

- **What exists (all VERIFIED in `index.html` and the stylesheets):**
  - `<html lang="en">`, a `<title>`, a meta description, Open Graph and Twitter card tags with a share image, favicons and a web manifest link.
  - Readable text in the HTML source: a four-paragraph About block in the Home tab; six rows of option labels; three tables of controls; the whisper rules; the credits text with six `<h2>` headings and a list; two Discord blurbs.
  - 19 anchors in total: 17 inside the credits (libraries, the course, a video playlist, the repository, licences, fonts) and 2 inside the Discord modal. All have `target="_blank" rel="noreferrer"`.
  - Native `<button>` elements for interface controls (41 of them), two `<form>` elements, real `<table>` elements for the controls.
  - Responsive rules: width breakpoints at 1100, 870, 800, 520, 440 and 360 px; `orientation: portrait` rules that stack the menu and the Discord modal; height breakpoints for the controls table; root font size 20 px, 18 px at 520 and below, 16 px at 440 and below; touch-specific rules through the `is-mode-touch` root class.
  - Touch support: the six DOM buttons, a virtual joystick, pinch to zoom, low quality chosen for mobile user agents, and an intro hint position tuned for the low-quality layout.
- **What does not exist (VERIFIED by searching `sources/` for the terms):**
  - No `<h1>` and no heading outside the credits; titles are `<div class="title">`.
  - No `<main>`, `<nav>`, `<header>`, `<footer>`, `<section>` or `<article>`.
  - No `<noscript>`.
  - No `aria-` attribute, no `role`, no `tabindex`, no `inert`.
  - No `alt` text: 44 `<img>` elements, of which 3 carry an empty `alt=""` and 41 carry none. Icon-only buttons (menu, map, close, the seven tabs) have no accessible name.
  - No `:focus` or `:focus-visible` rule in any stylesheet, and `button, input { outline: inherit }` in the reset.
  - No `prefers-reduced-motion`, no `prefers-color-scheme`, no `matchMedia` call.
  - No project, lab or career content anywhere in the HTML. Of the eight social destinations in `data/social.js`, only Discord appears as HTML links.
  - No structured data and no canonical link. (`robots.txt` and a sitemap would live in `static/`, which was not downloaded.)
  - No `try`/`catch`, no "unsupported" message, no fallback page.
- **Behaviour in specific situations:**
  - **No WebGPU:** the renderer is three's `WebGPURenderer` with `forceWebGL: false`. The Options panel checks `backend.isWebGLBackend` and shows a red "WebGL" badge with a performance warning, and a pre-render step is skipped. **INFERRED:** the fallback to WebGL 2 itself is done by three.js, not by this code.
  - **No WebGPU and no WebGL 2:** **INFERRED:** `await rendering.setRenderer()` rejects, `init()` stops, and the visitor sees the background gradient with no message. The menu trigger is in the DOM but slid out of view by the `intro` filter class.
  - **JavaScript off:** **INFERRED** from the CSS defaults: the menu and modals are `display: none`, both corner buttons are `display: none` until `is-started` is added, the touch buttons are `display: none`. The page is a blank gradient. The texts listed above are in the source but not displayed.
  - **A crawler or resume parser that does not run JavaScript** receives the meta tags and the texts listed above, and nothing about projects, experiments or career; of the social destinations it receives only the two Discord links.
  - **A screen reader:** **INFERRED:** on load there is a canvas with no fallback content and two unnamed buttons. Once the menu is open its content is exposed, but all seven content blocks are exposed at once, because inactive blocks are hidden with `opacity: 0` and `pointer-events: none` rather than `display: none`. Focus is neither moved into the panel nor trapped nor restored. Both corner buttons cancel every `keydown`, so they cannot be activated from the keyboard; Escape and M are the keyboard routes. In-world content has no non-visual route at all.
  - **Reduced-motion preference:** ignored. Camera moves, elastic tweens, confetti and wipes always play.
  - **Mobile portrait:** supported by the rules listed above; in the canvas, the cinematic camera backs away by an amount proportional to how far the aspect ratio is from the ideal, so the board still fits.
  - **Storage blocked:** **INFERRED:** `localStorage.getItem` is called unguarded while the first objects are constructed, so a browser that throws on storage access would stop the boot.
- **Other observations:** the page loads Google Analytics and Google Fonts from third-party hosts. The Open Graph `site_name` is the name of the author's course rather than of the site. The four preload links have no query string, while the code requests the same files with `?cb=1` appended. **INFERRED:** the preloaded responses are therefore not the ones the code uses.

- **Transfer: ADAPT by inverting the priorities; this is where the two projects must differ most.** folio-2025 is a game that contains a portfolio; the plain document is not a goal there. For a portfolio that must stay readable:
  - **Keep the existing page as the document.** The hero, About, Skills, Experience, Projects and Contact stay as server-delivered semantic HTML. The world is an enhancement loaded on request and never the only route to content.

## 3. Cross-cutting patterns worth copying

1. **A place in the world opens real HTML.** The Achievements, Controls and Behind-the-scene points do nothing but call `menu.open('<tab>')` and hide themselves until that panel's `close` event (`sources/Game/World/Areas/BehindTheSceneArea.js:117-148`). Applied consistently, this single pattern lets a game world and a semantic document share one copy of the content.
2. **Input contexts as a filter set.** Actions declare the contexts they belong to; UI layers swap the active set (`sources/Game/Inputs/Inputs.js:183-202`, `sources/Game/Menu.js:233-234`, `sources/Game/ClosingManager.js:90-108`). There is exactly one place that decides whether a key does anything.
3. **Interface state mirrored on the root element.** `is-started`, `is-mode-*`, `is-gamepad-*`, `input-filter-*`, `is-audio-muted`, `is-server-offline` are classes on `<html>`, and CSS does the rest: hide a trigger, swap an icon, pick a button glyph, hide whole features. In a Tailwind project the equivalent is a few `data-` attributes on the root and variants keyed on them.
4. **One owner for Escape/back** with an explicit priority order (`sources/Game/ClosingManager.js:21-57`).
5. **Small explicit state machines for anything that animates open and closed** (`CLOSED/OPENING/OPEN/CLOSING` in `Menu`, `Modals`, `ProjectsArea`, `LabArea`), so half-open states are never ambiguous. Presence animation in framer-motion gives the same guarantee with less code.
6. **Press opens, release acts.** One key opens a view on press and follows a link on release, and the release only counts once the view is fully open (`sources/Game/World/Areas/ProjectsArea.js:143-149`, `:1307-1311`).
7. **Hints that match the device and stop when understood.** One shared key icon swapped on device change (`sources/Game/InteractivePoints.js:120-155`); a hint board that stops hopping after the first use (`sources/Game/World/Areas/ProjectsArea.js:1121-1139`, `:1431`); the Controls tab preselected for the device (`sources/Game/World/Areas/LandingArea.js:110-118`).
8. **Named anchors in the level file, behaviour in code.** `References` turns a naming convention into a lookup table (`sources/Game/References.js:11-31`); zone radius comes from an object's scale (`sources/Game/World/Areas/Area.js:72-83`). Level edits do not need code edits.
9. **Lazy at every scale.** Two resource batches so the first screen needs four small files (`sources/Game/Game.js:103-109`, `:132-179`); the socket connects after the intro (`sources/Game/Reveal.js:222`); the map builds on first open (`sources/Game/Map.js:17-23`); the flag list enters the DOM on first open (`sources/Game/InputFlag.js:171-173`); thumbnails load when first visible (`sources/Game/World/Areas/LabArea.js:995-998`); content images prefetch one ahead (`sources/Game/World/Areas/ProjectsArea.js:435-466`); the Konami model loads on demand (`sources/Game/KonamiCode.js:59-61`).
10. **One gesture, three jobs.** The start gesture is consent, audio unlock and input enable at once (`sources/Game/Reveal.js:149-175`).
11. **Cover, change, uncover** for every teleport (`sources/Game/Player.js:469-488`).
12. **A sound registry with two hooks.** `onPlay` for per-trigger variation, `onPlaying` for per-frame binding to state, plus groups and an anti-spam interval (`sources/Game/Audio.js:45-145`, `:713-768`). The design is independent of whether a sound is a file or an oscillator.
13. **Achievements as data with shared counters and `Set`-based groups**, persisted as one blob and replayed silently on load (`sources/data/achievements.js`, `sources/Game/Achievements.js:25-36`, `:308-392`).
14. **Readability boost when content is focused.** The shade mix flattens lighting on content surfaces while a board is open (`sources/Game/World/Areas/ProjectsArea.js:211-223`, `:1324-1325`). In a 2D pixel world the analogue is dimming the scene behind an open panel.
15. **A toast queue with hold-on-hover, a click action and de-duplication ids** (`sources/Game/Notifications.js:59-175`).
16. **Text as a mask, colour from the material** (`sources/Game/World/Areas/ProjectsArea.js:264-290`), with nearest filtering for crisp edges: the right recipe for short pixel-font labels in a canvas.

Patterns to avoid copying:

- Content that exists only inside the canvas or inside textures (2.4 to 2.7, 2.10).
- `window.open` in place of anchors (2.12).
- Icon-only controls without names, removed focus outlines, cancelled key events on buttons (2.15, 2.30).
- Unversioned, unguarded `localStorage` access (2.25).
- No failure path during boot (2.24).
- An eight-argument positional factory with the same three callbacks repeated at every call site (2.13).
- Several physical buttons mapped to two actions with no way to consume the input (2.14).
- Absolute asset paths. The HTML head uses `/favicons/...` and `/respawns/...` (`sources/index.html:32-42`) although the build is configured with `base: './'` (`vite.config.js:11`). Under a GitHub Pages sub-path such paths resolve to the wrong place; build every URL from `import.meta.env.BASE_URL`.

## 4. Could not verify / open questions

1. **What anything looks like.** `static/` was not downloaded, so the appearance and layout of every area, the wording of the intro hints and blackboards, the map pictures, the menu preview pictures and the key icons are unknown. Descriptions of scenery in section 2 are inferred from object names in code.
2. **Actual image sizes and weights.** The code declares 960 x 540 and 240 x 135 but never uses those numbers (`sources/Game/World/Areas/ProjectsArea.js:336-337`, `sources/Game/World/Areas/LabArea.js:795-796`). The total download size of the 40 + 4 boot resources and of the 81 sounds is unknown.
3. **Server behaviour.** Storage, limits, moderation, validation of race times, the reset schedule and the rule "one whisper per user" are stated in the HTML or implied by message shapes; the server code is not public (`sources/index.html:710`).
4. **Gamepad cross bound to both `interact` and `close`.** Reading `sources/Game/Inputs/Inputs.js:204-236`, `sources/Game/Player.js:237` and `sources/Game/ClosingManager.js:16`, `:46-51`, one press should open the Projects or Lab board and then reach the close branch in the same call, closing it again. The menu has a gamepad guard (`:38`); these views do not. This needs a real gamepad to confirm. If true, it would also mean a gamepad user cannot follow a project link, since cross is the only pad button bound to `interact`.
5. **Pop-up blocking.** In-canvas clicks and gamepad presses reach `window.open` from the animation tick rather than from inside a DOM event handler (`sources/Game/Inputs/Pointer.js:183-190`). Whether browsers allow this in all cases was not tested.
6. **Font timing.** No code waits for web fonts before drawing canvas labels (`sources/Game/InteractivePoints.js:216-247`). Whether a label can be drawn in a fallback font on a slow connection was not tested.
7. **Preload links.** The preloaded URLs lack the `?cb=1` suffix the code requests (`sources/index.html:39-42` versus `sources/Game/Game.js:102-107`). Whether browsers reuse the preloaded responses was not tested.
8. **Live configuration.** The values of `VITE_GAME_PUBLIC`, `VITE_LOG`, `VITE_MUSIC`, `VITE_COMPRESSED` and `VITE_SERVER_URL` on the production site are not in the repository. In particular, whether `window.game` is exposed (which would make the "cannot be achieved" entry achievable from the console) is unknown.
9. **Three.js fallback.** That `WebGPURenderer` silently falls back to WebGL 2 is library behaviour assumed from how the code uses it (`sources/Game/Rendering.js:40-45`, `sources/Game/Options.js:66`); the exact behaviour with neither API available was not observed.
10. **Keyboard trap on the corner buttons.** Both cancel every `keydown` (`sources/Game/Menu.js:66-69`, `sources/Game/Map.js:130-133`). That this also blocks Tab once such a button has focus is inferred from DOM semantics, not observed.
11. **Hidden menu panels and assistive technology.** That all seven content blocks are exposed at once when the menu is open is inferred from the CSS (`sources/style/menu.styl:198-216`), not checked with a screen reader.
12. **`robots.txt`, sitemap, manifest contents and the share image** live in `static/` and were not examined.
13. **A design question for the target project, not answerable from this source:** folio-2025 never shows how a 3D world and a readable document coexist, because it has no document. The DOM-panel pattern in 2.9 is the nearest precedent, but an opt-in world layered over an existing semantic page (routing, scroll position on return, deep links to a section from inside the world, the browser back button) has no counterpart here to study.
